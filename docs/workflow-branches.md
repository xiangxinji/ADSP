# 工作流分支与异常端点

ForgePilot · 铸航的工作流由根触发器、资产操作节点、同步执行和异步执行节点组成。
所有节点必须从根触发器可达。每个输出端点只能连接一个子节点，每个子节点只能
有一个上游；不支持环路或跨分支合流。最多支持 50 个节点。

## 节点取值与输出

手动运行时可输入一个 JSON 对象作为根触发器输出。资产操作节点的参数支持三种取值：

- 固定值：直接使用编辑器中填写的字符串或布尔值。
- `$root.path`：始终读取本次运行的根触发器输出，例如 `$root.release.branch`。
- `$prev.path`：读取当前执行路径的上一份值，例如 `$prev.branch`。

点号可以继续读取嵌套对象，数组使用数字下标，例如 `$root.releases.0.branch`。
表达式会替换整个参数并保留原始类型，不是字符串模板；目标字段类型必须与资产操作
契约一致。每个资产操作成功后都按共享契约校验输出字段和类型，再把该输出交给正常
后续节点。取值路径不存在或类型不匹配时，当前节点在调用外部命令前失败。

正常连线把成功输出作为下一份值。异常连线透传进入失败节点时的原数据，只在保留字段
`error` 下附加 `{ code, message }`，不使用失败节点的参数覆盖业务字段，也不伪造成功输出。
例如输入 `{ id, name }` 时，异常子节点仍可使用 `$prev.id`、`$prev.name`；错误通过
`$prev.error.code`、`$prev.error.message` 读取。原有业务字段 `code`、`message` 保持不变，
嵌套对象、数组字段及其类型也不变；顶层数组的元素保留为异常上下文中的数字键，仍可用
`$prev.0.id` 访问。异常上下文是对象，不是可直接交给逐项执行节点的数组。
连续异常只替换 `error` 为当前错误，不修改根输入或其他并发分支的数据。旧配置若使用
`$prev.code` 或 `$prev.message` 读取错误，需分别改为 `$prev.error.code` 和
`$prev.error.message`；原有运行历史不改写。处理节点成功后仍按正常规则传递它的成功输出。

同步或异步节点的执行子端点继承进入控制节点时的值；控制节点的「完成」和「异常」
出口则获得 `{ branches, selectedPort }`。因此嵌套控制节点不会读取尚未完成的父节点输出，
也不会跨并发分支读取兄弟节点数据。运行历史同时保存配置表达式、实际输入、根输出和
节点输出。

## 配置资产操作异常端点

1. 从节点库添加资产操作，填写它的必填参数。
2. 点击节点卡片上的「添加异常端点」，或在右侧「节点配置 → 异常端点」添加。
3. 从下拉框选择当前操作契约声明的错误码。可添加多个端点，同一错误码只能选一次。
4. 拖动红色异常圆点连接到处理节点；也可点击异常端点，再点击子节点完成连线。
   子节点的「上游节点 / 端点」下拉框也可以指定该异常出口。
5. 正常后续操作连接到节点底部的正常出口。保存后点击运行，或直接「保存并运行」。

例如，创建分支操作可以配置：

```text
手动触发 → 创建分支
             ├─ 正常执行 → 正常后续操作
             ├─ repository.branch-already-exists → 分支已存在时的处理节点
             └─ repository.source-not-found → 原分支不存在时的处理节点
```

- 成功时只执行正常路径，所有异常路径及其子树标记为「已跳过」。
- 失败时按 `data.code` 精确匹配，只执行匹配且已连接的异常路径；不会继续正常路径。
- 未匹配、未配置端点或匹配端点尚未连线时，当前路径失败并停止。
- 异常路径可以继续连接多个操作，也可以包含同步、异步节点或更多异常端点。
- 未预期的程序异常被脱敏为 `workflow.operation-failed`，不会根据错误描述猜测分支。
- 原始节点的失败状态和错误码始终保留。即使处理节点成功，整个运行仍标记为失败，
  方便审计；这里的异常端点不是自动重试，也不把失败变成成功。

更换错误码不会改变端点 ID 或现有连线。删除端点只删除它的连线，不删除子节点；
被断开的节点必须重新连接或手动删除后才能保存。旧工作流无需添加异常端点，行为不变。

## 同步与异步：自动按数组逐项执行

两种流程控制节点都只有一个固定的「逐项执行」子端点（`item`），不再需要添加、
重命名、排序或删除子端点。「完成」「异常」作为可选结果出口保留，不是额外的执行子端点。

1. 添加一个直接输出数组的上游节点，例如「获取所有仓库」。
2. 连接到「同步执行」或「异步执行」。
3. 将「逐项执行」连接到唯一的子节点，例如「创建分支」，只需配置这一个节点。
4. 将子节点的资产来源设为「输入值」，仓库 ID 填 `$prev.id`；其他参数可以使用字面量、
   当前元素的字段，或 `$root` 中的根数据。
5. 按需连接「完成」「异常」，保存后运行。

```text
手动触发 → 获取所有仓库 → 同步执行 / 异步执行
                          ├─ 逐项执行 → 创建分支 → 后续操作
                          ├─ 完成 → 全部元素成功后的操作
                          └─ 异常 → 存在失败后的处理操作
```

上游数组有多少个元素，就在内部执行多少次同一个子流程，不复制画板节点。
每次子节点的 `$prev` 是当前数组元素，例如 `$prev.id`，不是整个数组；无需写 `$prev.0.id`。
`$root` 始终是根触发器输入，子节点之后的节点仍通过 `$prev` 读取紧邻的前一个操作结果。

### 同步执行

- 按上游数组索引从小到大逐项执行，不受节点位置、名称或连线顺序影响。
- 等待当前整条子流程结束，包括嵌套控制节点及异常处理，再启动下一个元素。
- 任一元素失败后，未启动的后续元素及对应路径记录为「已跳过」，执行一次异常出口。
- 父节点错误码为 `workflow.sync-branch-failed`，保留原始失败节点和错误码。

### 异步执行

- 为每个数组元素并发启动同一个子流程，输入、输出和状态相互隔离。
- 等待所有元素的完整子流程及异常处理结束；即使某项失败，也不会提前结束其他项。
- 全部成功执行一次完成出口；存在失败执行一次异常出口。
- 父节点错误码为 `workflow.async-branch-failed`，执行结果始终按输入数组顺序展示。

### 边界与记录

- 空数组不执行子节点，直接进入完成出口。
- 非数组输入不执行子节点，产生 `workflow.control-input-not-array` 并进入异常出口。
  错误对象也不是数组；若在操作异常路径中执行流程控制，应先连接一个输出数组的操作。
- 端点必须连接唯一子节点；即使预期数组为空，保存时也会校验完整子流程。
- 完成/异常出口的 `$prev` 为 `{ branches, selectedPort }`。`branches` 按数组顺序记录
  零基索引 `index`、原始元素 `input`、状态及原始错误。
- 点击执行记录中的重复节点，在「逐项执行记录」中选择具体元素，查看独立输入、输出、
  开始/结束时间和错误；嵌套执行显示完整索引路径，不以最后一次执行覆盖其他结果。
- 已成功的外部操作不会回滚，也不会自动重试。异常处理成功不抹除原始失败。
- 两种控制节点可以嵌套，但每层的直接上游都必须输出数组。服务重启会将未完成的
  逐项记录标为中断或跳过，不自动重放外部操作。

### 旧工作流

读取旧定义时，原执行端点映射到固定 `item` 端点，节点和连线不删除。
原来只有一个已连接子节点的配置无需手动迁移端点；仍需确保上游输出数组。
原来连接了多个不同子节点的配置会提示「每个输出端点只能连接一个下游节点」，
需明确保留唯一子节点并整理其他连线后才能保存和运行，不会静默选择或删除旧子流程。
历史运行快照及其原始结果保持不变。

## 运行与验证

运行前检查整个图的资产归属、契约参数和端点，包括本次可能不会被执行的异常路径。
不合法的配置会在任何外部操作之前被拒绝，不创建运行记录。

运行记录保存当次节点、端点和连线的只读快照；后续修改不会改写历史。
运行过程中关闭页面不会取消任务，同一个工作流不能重复启动。
所有未选择路径均记录「已跳过」，而非一直停留在等待状态。
