# 工作流节点：复用另一个工作流

工作流节点将同一项目中的另一份已保存工作流作为一个节点执行，并在父工作流的
执行记录中展示内部进度。它不是新的资产类型，也不改变资产操作契约或 Markdown
资产快捷入口。

## 配置与使用

1. 在项目的工作流列表中创建子工作流，配置根触发器、节点及连线并保存。
2. 打开父工作流，从左侧「流程节点」点击或拖入「工作流」节点。
3. 在右侧选择「执行工作流」，可自定义该调用节点的名称。
4. 连接上游及可选的下游，保存后运行父工作流。
5. 打开「执行记录」并点击工作流节点，展开内部节点查看状态、实际输入、输出与错误。
   同步或异步逐项调用时，先选择具体的「逐项执行记录」，每一项都保留独立子运行。

```text
父工作流根数据 → 工作流节点 → 下一步
                   │ 等待完成
                   └─ 子工作流根数据 → 内部节点 A → 内部节点 B
```

## 输入与输出

- **输入**：上游输出原样作为子工作流的根数据。直接连接父根触发器时，传递父根数据。
  子工作流内通过 `$root.xxx` 读取，首个内部节点也可以通过 `$prev.xxx` 读取。
  对象和数组都可传递，数组使用 `$root.0.id` 等数字下标路径。
- **作用域**：子工作流的 `$root` 仅表示本次传入的数据，不隐式读取父工作流最初的
  根数据；每次调用独立，包括同一工作流被多个节点或多个数组元素复用的情况。
- **输出**：子工作流实际执行路径的最终输出成为调用节点输出，下游用 `$prev.xxx`
  继续读取。若最后执行的是没有后续出口连线的流程控制节点，输出为它的逐项结果。
  直接输出数组的子工作流可以连接父工作流的同步或异步节点。
- **执行顺序**：父节点等待子工作流内部路径全部完成才继续，不是后台触发后立即成功。
  被调用的工作流直接进入其根节点，不等待该触发器对应的外部事件。

例如，父节点输出 `{ "id": "仓库ID", "name": "feature/demo" }`，子工作流的
「创建分支」可将仓库来源设为输入值，参数配置为 `repositoryId: $root.id`、
`branch: $root.name`、`source: main`。执行后父节点直接输出创建分支的结果。

## 状态与快照

- 画布显示调用节点状态与内部成功节点数量；执行面板每秒更新内部节点状态。
- 多层调用可逐层展开；内部迭代记录保留各项的输入、输出和错误。
- 子工作流失败时，父调用节点为失败，普通后续节点跳过。内部已按资产操作异常端点
  正常处理的错误不会再次使父调用失败。调用节点本身不配置资产异常端点。
- 启动前校验所有引用定义和操作参数，并冻结所有已保存的定义快照。之后编辑子工作流，
  不影响当前运行，包括尚未开始调用的子工作流。
- 子运行存储在父运行的 `steps[].childRun` 或 `steps[].executions[].childRun` 中，
  不单独出现在子工作流自己的手动运行历史。现有运行查询 API 路径不变。
- 服务重启后，未完成的父子运行均记为中断，不自动重试；已完成的内部结果保留。
- 当前运行引用的工作流不能删除或另行直接手动启动；运行结束后删除被引用的定义不会
  删除父运行中的历史快照，但后续重新运行父工作流会提示引用不存在。

## 校验与稳定错误码

| 错误码 | 含义 |
| --- | --- |
| `workflow.subworkflow-not-found` | 引用的工作流或执行快照不存在 |
| `workflow.subworkflow-project-mismatch` | 引用不属于当前项目 |
| `workflow.subworkflow-cycle` | 直接调用自身或形成间接循环 |
| `workflow.subworkflow-depth-exceeded` | 超过 8 层嵌套，包含当前工作流 |
| `workflow.subworkflow-not-ready` | 子工作流未配置根触发器或没有节点 |
| `workflow.subworkflow-failed` | 内部执行失败，原始错误保留在子运行中 |
| `workflow.interrupted` | 服务重启导致尚未完成的执行中断 |

保存及启动前校验失败时不创建运行、不产生操作副作用；其他节点参数和资产校验继续
使用既有错误契约。预期错误通过 HTTP `data.code` 或执行步骤的 `error.code` 返回，
不依赖翻译后的错误描述。跨项目引用、循环引用和超限嵌套在服务端强制拒绝。
